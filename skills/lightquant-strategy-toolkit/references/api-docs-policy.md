# API 文档与版本策略

## 开源仓库应包含什么

- 包含本技能中的精简平台参考：生命周期、API 模块、常见差异、数据和订单保护、转换规则。
- 为平台官方或券商提供的完整文档提供名称、访问入口（若可公开）、版本/发布日期与访问日期；每次开发只查当前任务涉及的章节。
- 只有在确认许可允许再分发时，才提交完整 API 文档、截图、帮助目录或示例代码。平台登录后可见、券商专属、带账户信息或许可不明确的资料不要上传。
- 不要把本机绝对路径、个人盘符、账号/口令、客户数据、策略源码样本或私有日志提交到公共仓库。

## 本套技能涉及的 API 文档与接口范围

源技能引用的资料名称如下；文件名来自维护者本机资料清单，开源使用者应替换为自己账号/券商提供的最新版副本或入口：

- **PTrade API 文档**：原文件名 `ptradeapi.html`，覆盖生命周期/调度、行情与历史数据、财务数据、证券与账户/持仓对象、订单与撤单、日志和运行环境。
- **PTrade 财务数据 API 文档**：原文件名 `财务数据api.html`，重点核对财务字段、返回结构、单位、报告期和数据可用时点。
- **PTrade 帮助资源**：`帮助_files/` 与 `财务数据_files/` 是 HTML 文档配套资源目录，不应当脱离主文档单独当作完整规范发布。
- **聚宽 API 文档**：原文件名 `JoinQuantAPI.pdf`，覆盖初始化与回调/调度、行情、财务/因子、下单、账户持仓、日志及回测环境。若平台控制台提供较新的版本，应使用控制台当前版本。

技能中涉及的代表性接口/对象类别：

- 生命周期与调度：`initialize`、`before_trading_start`、`handle_data`、`after_trading_end`、`run_daily`、`run_weekly`、`run_monthly`。
- 行情与证券范围：`get_price`、`get_history`、`history`、`attribute_history`、`get_current_data`、`get_index_stocks`、`get_all_securities`。
- 财务与因子：`get_fundamentals`、`query`、`get_extras` 及估值/财务字段。
- 交易与账户：`order`、`order_value`、`order_target`、`order_target_value`、上下文/组合/账户/持仓对象。
- 日志与配置：平台日志对象、日志级别、手续费和滑点设置接口。

上述名称是旧技能中提到的代表性 API，并非对每个券商版本或每个运行模块的可用性承诺；使用前按目标环境文档核对。

## PTrade 版本兼容声明

PTrade 可能有券商部署/接口版本差异。涉及接口兼容时，至少注明券商/部署标识、API/客户端版本（可获得时）、运行环境（回测/模拟/实盘）、Python 环境（可获得时）、参考文档版本/日期和验证日期。未确认项写“未确认”。不应只笼统写“支持 PTrade”。

本机找到的参考文件为**国金版本**。其 API 变更记录顶部列有 `PTrade1.0-QTV202401.05.032`，文档还区分 Python 3.5 与 Python 3.11 的 API/返回结构。应把前者注明为“本地文档所列最高 API 变更版本”，不能当作当前已部署客户端版本；实际券商客户端版本和当前 Python 环境仍需另行确认。配套财务 HTML 未识别到单独版本号。

## 聚宽版本兼容声明

记录所依据的文档名称或访问日期、运行模块（研究、回测、模拟或交易）、可确认的 Python/依赖环境和验证日期。若平台未提供稳定版本号，直接写“平台版本号未公开/未确认”，不要编造语义版本号。

## 文档更新

API 摘要是辅助索引，不是官方规范。维护者应在行为/参数变化时复核所用平台资料，记录复核日期，并将“官方文档事实”“本地环境观察”“推断或兼容假设”分开标注。

完整 PTrade 原始 HTML 和资源目录目前不随技能包自动分发。文件没有发现明确的再分发许可证；公开前需确认券商/平台授权。仓库的 MIT 许可证不覆盖第三方平台文档、商标或截图。
