# PTrade 平台参考

本文件是跨券商的工作提示，不是某一券商、客户端版本或运行环境的完整 API 规范。PTrade 部署可能在回测、模拟、实盘、券商版本、Python 与依赖包上不同。使用者应以所属券商提供的文档、客户端版本及实测结果为准。

## 当前随 LightQuant 仓库记录的参考版本

仓库内国金版本 API 文档记录到的最高接口变更版本为 `PTrade1.0-QTV202401.05.032`，并同时描述 Python 3.5/3.11 环境。此标识不能证明使用者当前安装的客户端版本。版本详情见仓库的 `api-docs/raw/ptrade/guojin/README.md`；独立安装本技能时请以自己券商提供的文档为准。

## 查阅范围

仅在策略实际用到时查对应文档章节：

- 生命周期与回调签名：`initialize`、`handle_data`、`before_trading_start`、`after_trading_end` 等
- 上下文、全局状态、组合、账户、现金、持仓与可卖数量
- 行情、历史数据、当前行情、证券信息、指数成分与交易日历
- 财务报表、财务指标、因子与基金净值
- 订单、目标仓位、撤单、订单状态及成交回报
- 定时调度、日志和回测/交易环境差异

## 兼容性和运行规则

- 分清“文档列出 API”与“当前券商账号/运行环境实际开放 API”。不能仅凭通用文档断言可用。
- 处理日期参数差异；如果同日 `start_date` 与 `end_date` 区间在环境中失败，可按平台文档优先使用 `count + end_date` 的历史数据形式。
- 不默认交易专用 ETF 辅助接口可在回测中使用。
- 不要把聚宽的暂停状态、日期对象、日志配置或上下文字段直接映射为 PTrade 等价项。按目标平台的字段语义逐项核对。
- 保留原策略实际使用的证券代码格式；只有存在明确格式冲突时才添加局部转换。
- 对 `get_history`、`get_price`、`get_fundamentals` 等结果按可能为字典、DataFrame、结构化数组、空值或 `None` 处理。
- 对结构化数组先检查字段名；访问 `[-1]`、`iloc[-1]`、列或字段前确认非空、长度足够且字段存在。
- `handle_data` 可能按分钟触发。日级选股、日计数和调仓必须加日期状态保护，不能每分钟重复计数。
- 新增状态在初始化回调中赋初值；明确每日计数、缓存、冷却期和信号状态的重置位置。
- 将 `order`、`order_value`、`order_target`、`order_target_value` 等调用的返回值当作可能失败或为空处理。只有获得可用成功证据后才更新状态。
- 买卖前逐条保护再平衡、止损止盈、补仓、清仓等路径：无效价格、停牌、涨跌停、现金不足、可卖数量、目标差额小于一手等。
- 诊断日志按数量汇总、限制样例数并节流重复信号；保留原始中文文件的真实编码，新文件优先 UTF-8。
