# 策略解读档案：字段定义与表达规范

默认按主技能中的 42 个字段顺序输出，每个字段写一至两句完整中文。若代码没有给出信息，写“代码中未明确给出”，不要用平台惯例补值。

| 序号 | 模块/字段 | 应说明的内容 |
|---:|---|---|
| 1 | 策略名 | 使用文件名或代码中的明确名称；都没有时注明未明确给出。 |
| 2 | 平台 | 在聚宽、PTrade、无法确认中识别，并简述启动、调度、数据、订单或代码格式证据。 |
| 3 | 策略类型 | 如 ETF 轮动、基本面选股、均线择时；不确定时注明未明确给出。 |
| 4 | 识别置信度 | 给出高/中/低和基于代码证据的原因。 |
| 5 | 初始化 | 参数、基准、费用、状态和定时任务设置。 |
| 6 | 盘前 | 数据准备、股票池筛选或交易开关检查。 |
| 7 | 盘中 | 按平台运行周期检查行情、信号、交易条件和风控。 |
| 8 | 调仓 | 频率、准确时间和调仓任务含义。 |
| 9 | 尾盘 | 尾盘任务及时间。 |
| 10 | 收盘后 | 收盘复核、日志、状态重置或下一交易日准备。 |
| 11 | 交易范围 | 指数成分、ETF 池、手工列表或全市场范围。 |
| 12 | 过滤条件 | ST、停牌、新股年龄、市值/估值、成交量/价格、涨跌停等具体条件。 |
| 13 | 排序因子 | 排序指标和方向；没有则说明未明确给出。 |
| 14 | 信号生成 | 产生买入、持有、卖出或防御信号的条件。 |
| 15 | 目标标的形成 | 候选如何成为最终清单，以及截断/数量上限。 |
| 16 | 触发条件 | 买入时间及前置条件/信号。 |
| 17 | 买入对象 | 买入候选或目标代码来自何处。 |
| 18 | 下单方式 | 按资金、目标市值、目标数量或数量增减等实际动作。 |
| 19 | 资金分配 | 等权、每槽现金、全现金、目标金额或其他公式。 |
| 20 | 买入限制 | 最小单位、可用资金、停牌/涨停检查、最大持仓等。 |
| 21 | 调仓卖出 | 目标清单变化或再平衡如何触发卖出。 |
| 22 | 止盈 | 仅陈述显式止盈阈值；不存在时注明未明确给出。 |
| 23 | 止损 | 显式阈值、是否启用及触发标的。 |
| 24 | 特殊情况卖出 | 涨停打开、市场风控、防御切换、空仓月份等其他退出。 |
| 25 | 目标持仓数 | 配置目标或未明确给出。 |
| 26 | 单票金额 | 单标的金额或计算公式。 |
| 27 | 总投入上限 | 全仓、现金预留、最大敞口或未明确给出。 |
| 28 | 现金处理 | 闲置现金、现金类 ETF、防御 ETF 或无目标时处理。 |
| 29 | 等权/加权方式 | 等权、按排名加权、满仓或未明确给出。 |
| 30 | 个股/单标的风控 | 单仓止损止盈、价格过滤、可卖检查等。 |
| 31 | 市场风控 | 指数择时、市场宽度、回撤或市场止损。 |
| 32 | 交易可达性风控 | 停牌、ST、涨跌停、最小单位、无效价格、流动性和订单规模。 |
| 33 | 空仓/防御机制 | 现金、货币 ETF、防御 ETF、空仓月份和无目标行为。 |
| 34 | 滑点 | 固定价差/比例等执行假设；未配置则注明。 |
| 35 | 交易费用 | 按买卖方向和资产类型报告税费/佣金。 |
| 36 | 最低佣金 | 明确数值或未明确给出。 |
| 37 | 成交假设 | 下单时间、目标数量/金额及代码可见的成交假设。 |
| 38 | 回撤 | 代码中回撤风险控制和缺口，不预测损失。 |
| 39 | 过拟合 | 参数密度、固定阈值、模型/指标复杂度体现的实现风险。 |
| 40 | 流动性 | 流动性过滤条件及可见缺口。 |
| 41 | 换手 | 调仓频率和代码中可能导致频繁交易的条件。 |
| 42 | 参数敏感性 | 哪些参数最影响策略行为，不建议改值。 |

## 普通中文表达

主档案应先描述用户能理解的动作，再在技术证据区提供实现依据。例如：

- `initialize`：写成“策略启动时完成参数、成本、持仓状态和定时任务设置”。
- `before_trading_start`：写成“每日开盘前判断日期并准备数据”。
- `handle_data`：写成“盘中按平台运行周期持续检查行情和交易条件”。
- `run_daily`：写成“每天指定时间执行某项任务”；`run_weekly` 写成“每周某日某时调仓”。
- `order_value`：写成“按指定资金金额买入”；`order_target` 目标为零时写成“清仓”；`order_target_value` 写成“把持仓市值调整到目标金额”。
- `get_price`：写成“读取历史或分钟行情”；`get_current_data`：写成“读取停牌、涨跌停、现价等当前状态”。
- `get_fundamentals`：写成“读取估值和财务数据”；`get_index_stocks`：写成“读取指数成分股”。
- 将 `stock_num=10` 翻译为“目标最多持有 10 只”；比例 `0.08` 按代码真实比较方向解释为“8% 阈值”，不能只看变量名。

技术标识集中于“平台 API 识别”“代码依据”等章节，写成“读取历史行情（`get_price`）”，不要只列函数名。平台识别示例：“代码使用聚宽初始化、定时调度、行情和财务查询，并采用聚宽证券代码格式，因此识别为聚宽。”

## 可选输出

- 用户要求评分时可附：平台识别、交易逻辑解释、风控识别、平台 API 识别、是否有胡编，各标通过/不通过或有/无。
- 用户要求 API 时按生命周期/调度、行情、财务/因子、订单、账户/持仓、日志/配置、证券信息分组。
- 用户要求 Excel 时，“总览”和自然语言档案的策略翻译列不得包含原始函数名、变量名、API 名或参数名；用独立区域存放 API 与转换风险。
- 转换风险要描述语义差异，如调度时点、数据返回结构、财务披露口径、订单回报、证券代码格式和平台专属能力，不输出孤立 API 清单。
