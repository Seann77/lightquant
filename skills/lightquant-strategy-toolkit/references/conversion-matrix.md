# 聚宽与 PTrade 转换矩阵

转换前先列出交易范围、筛选与排序、信号、调仓频率、订单规则、仓位/现金处理、风控、财务数据可用性。转换过程中按以下类别逐项核对：

| 类别 | 核对要点 |
|---|---|
| 生命周期 | 初始化、盘前、盘中、盘后入口和回调参数是否对应 |
| 调度 | 日/周/月频、触发时间、交易日偏移和重复触发行为 |
| 证券代码 | 市场后缀、指数代码、ETF 格式、API 接受格式 |
| 行情数据 | 日线/分钟线、当前数据、复权、缺失值、返回结构和时间边界 |
| 财务/因子 | 字段名称、单位、报告期、披露可用时间、查询返回类型 |
| 信号与排序 | 因子方向、并列处理、过滤顺序、候选池为空时行为 |
| 订单 | 按数量/金额/目标仓位下单、撤单、部分成交、成功返回值 |
| 账户持仓 | 现金、总资产、可卖数量、成本、持仓字段和刷新时点 |
| 状态管理 | 全局状态生命周期、日重置、缓存与订单后的更新规则 |
| 日志和编码 | 日志接口、节流、中文源码编码、异常可见性 |

## 聚宽转 PTrade

- 核对调度、上下文对象、日志接口、日期参数、暂停状态字段和 ETF 辅助能力。
- 重新确认历史/分钟数据的返回形状、字段和当日边界，不能把同名 API 当作行为完全一致。
- 重新确认订单返回值、可卖数量和交易环境；交易状态只能在有成功证据后更新。
- 检查财务查询字段、表结构和公告可用时间；无法重现时明确说明，不以不相干代理字段冒充原字段。

## PTrade 转聚宽

- 移除平台专属的上下文字段和回调假设，重映射到聚宽生命周期与调度。
- 核对股票/ETF代码、行情时间范围和复权口径。
- 明确目标金额/目标数量函数、订单结果与成交回报差异。
- 重新验证财务/因子字段和可用时间，避免筛选语义悄然变化。

## 近似与阻塞策略

若目标平台没有等价能力：

1. 优先寻找目标平台的原生等价数据/交易能力；
2. 仍缺失时，写明近似方式、使用数据、单位假设和影响的策略行为；
3. 原有硬过滤缺少数据时不得静默放行；
4. 若无法在不改变关键交易语义的前提下实现，明确列出所需用户资料或标记为平台能力阻塞。
